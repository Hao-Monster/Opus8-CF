# P6.3/P6.4 多视角健康探测与按节点优选 IP

## 健康判定

`healthcheck-nodes` 每 10 分钟从两个位置执行真实的
VLESS-over-WebSocket 出口测试：

- GitHub Actions Runner；
- 默认落地 VPS（通过 SSH 在 VPS 本机执行同一探测脚本）。

任一可用视角成功时，节点不会因为单一网络路径故障而被误封；两个可用视角都失败时，
才会计入一次直连失败。连续 3 次直连失败后节点从订阅移除，连续 2 次成功后恢复。
落地/WARP 路由失败只会把节点标记为 `degraded`。

如果 VPS SSH 暂时不可用，健康任务会明确记录 `github-only fail-safe`，继续使用
GitHub Runner 的结果，不会把“视角缺失”本身当作节点失败。每次健康事件的
`details.vantages` 会保留两个视角的成功状态、延迟和错误摘要。

## 部署冒烟

节点部署先在 GitHub Runner 上做真实 VLESS 冒烟。如果该路径在部署传播窗口内持续失败，
会自动改由落地 VPS 再测一次。任一视角成功即可完成部署；所有可用视角都失败才会让部署失败。

SSH 与 SOCKS5 凭据是两组独立配置：

- `SERVICES_IP`、`SERVICES_USER`、`SERVICES_CODE`：VPS 地址与 SSH 登录；
- `SOCKS_USER`、`SOCKS_PASSWORD`：Dante SOCKS5 登录；
- `SERVICES_SSH_PORT`：可选，未配置时使用 `22`。

## 优选 IP 安全准入

`optimize-ip` 每 4 小时执行一次：

1. CFST 负责发现和排序最多 64 个通用候选 IPv4；
2. 额外收集每个节点在 GitHub Runner 与落地 VPS 上实际解析到的 IPv4，每个节点去重后最多探测 32 个候选；
3. 候选以最多 4 个并发按节点执行 GitHub Runner + 落地 VPS 的真实
   VLESS + TLS SNI + WebSocket + 出口 HTTP 测试；
4. 按两侧较慢延迟 `max(github, landing)` 排序，每个节点最多发布 8 个通过双视角验证的 IP。

控制面只接受包含主机名、双视角、验证时间和过期时间的版本 3 按节点 IP 池。池有效期为
12 小时；某个节点没有安全候选或记录过期时，只让该节点回退域名，不影响其他节点已经通过
验证的 IP。版本 2 全局池和旧的纯数组池不会进入订阅。若全部候选均失败，任务会以安全
空操作结束并继续使用节点域名，这属于正常回退而不是节点故障。

订阅端再以 `SUB_MAX_OPTIMIZED_IPS_PER_NODE` 控制实际展开数量，允许 1–8。部署工作流默认从 3
开始分阶段放量；确认订阅体积、客户端导入和节点质量稳定后，可在 GitHub Actions Variables 中
提高到 8。无有效优选 IP 的 Worker 始终只下发一条原始域名配置，不使用未经本轮验证的
`preferred_ip` 填充数量。

临时探测用户创建后，每个节点最多等待 60 秒完成两侧策略传播。仍未通过域名基线的节点会
被本轮跳过并继续使用域名，其他节点照常验证；未通过基线的节点绝不会进入优选 IP 池。

`smoke-vless.py --connect-host <IP>` 只覆盖 TCP 连接地址，TLS SNI 和 WebSocket
`Host` 始终保持节点域名，验证方式与实际订阅连接一致。
